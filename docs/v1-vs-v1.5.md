# MeshTrain V1 vs V1.5

V1.5 keeps V1's static placement and exact training semantics. It changes **how** each step runs:

| | V1 | V1.5 |
|---|---|---|
| Schedule | GPipe-style fill/drain | 1F1B (GPipe kept as a baseline) |
| Sends | blocking, on the compute thread | asynchronous sender thread per link, bounded queue |
| Receive buffers | new allocation per message, two extra copies | received in place into pooled buffers, released after backward |
| CUDA staging | pageable `.to("cpu")` | pinned pool buffers, dedicated transfer stream, CUDA events |
| Memory planning | params + grads + optimizer + activations, 15% margin | + AdamW step temporaries, buffers, workspace, schedule-aware activations, per-backend safety factor and framework reserve; runtime validation; startup replan |
| Planner | compute + network | + D2H/H2D per boundary, overlap, boundary-size tie-break |
| Observability | per-step totals | interval timeline (Chrome/Perfetto), overlap/exposed/idle, prediction accuracy |

Every row below is generated by `meshtrain benchmark pipeline` (local processes) or
`meshtrain benchmark pipeline --cluster --config ...` (real cluster). Each section states the
environment and link it was measured with.

## Research questions

* **Q1, cost of blocking communication in V1:** see "exposed comm" for `V1: gpipe + blocking`.
* **Q2, how much async transfer hides:** see "overlap" and "exposed comm" for the async modes.
* **Q3, activation memory saved by 1F1B:** see "peak act MB (stage 0)" and "saved mb (stage 0)".
* **Q4, CUDA + CUDA + MPS correctness:** `meshtrain experiment device-correctness --devices ...`
  and `meshtrain results record` on the real cluster. **Not measured yet: no CUDA/MPS hardware in
  the development environment.**
* **Q5, topology-aware vs equal placement:** `prediction_accuracy.json` in each run, and
  `meshtrain experiment placement`. Real-cluster comparison pending.
